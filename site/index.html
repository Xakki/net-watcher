Net Watcher is a proposed measurement study of how public network records change over different time scales.

Current status

Method before findings

Draft only. No study is active. No results are published.

This page describes intent and limits; it is not evidence of collection, operation, or deployment.

Measurement frame

Keep each clock honest.

A public registration record can describe an earlier event, routing state can be observed later, and cited sources can be checked together in a later validation snapshot. The proposed method treats those moments as separate dimensions rather than one timeline.

  1. A

    Registration-event clock

    When the event or interval described by a public registration record occurred.

  2. B

    Routing-observation clock

    When public routing state is observed.

  3. C

    Validation-snapshot clock

    When cited public sources are checked together; repeated snapshots may show change across a declared window.

SYNTHETIC EDUCATIONAL CASE

Earlier registration change, later route change

A registration object appears to change before a route change is observed. The ordering is real inside this fixture, but it does not establish causation.

Fixture rules

This is a teaching fixture, not a captured record. The registration clock describes when a record says its version was processed; that claimed time is not necessarily the real-world event time. The routing clock describes when a vantage point observed a route, including propagation and sampling delay. The validation clock describes when the two descriptions were checked together.

Three separate clocks are used here. Assume only minute-level resolution and no aligned clocks. A timestamp such as t−20 minutes is relative to the route observation, not a wall-clock claim.

Registration clock t−20: version processed
A record reports a version transition.
Routing clock t−5: route seen
One vantage point reports a route state.
Validation clock t+10: sources checked
The descriptions coexist in one review snapshot.

Tempting conclusion

“The registration change caused the route change because it came first.”

Evidence audit

  1. Label the claim. “Version processed at t−20” is a registration-record claim, not proof of when an underlying change happened.
  2. Label the observation. “Route seen at t−5” is an observation from one vantage point, not the route’s first appearance everywhere.
  3. Test alignment. Minute-level resolution and unknown delays leave overlap and ordering uncertainty.
  4. List alternatives. The changes may share an unobserved trigger, be independently scheduled, or reflect processing and propagation delays.

Defensible conclusion

The fixture supports an association in reported order: a registration-object version transition was reported before a route state was observed. It does not establish causation, intent, ownership, responsibility, or the direction of influence. No hidden ground truth is asserted.

What would reduce uncertainty

Conceptually, uncertainty would narrow with independently documented event semantics, aligned clock precision, repeated observations from distinct vantage points, and a pre-specified comparison window. Those are evidence requirements for a future approved study, not instructions to collect data now.

Self-check with worked answer

Question: Which statement is supported: (A) the object change caused the route change, (B) the two reported changes have an ordering in this fixture, or (C) the object owner intended the route change?

Worked answer: B only. The fixture defines two reported times and a later validation snapshot. It does not define aligned clocks, first-seen times across the network, a mechanism, or intent. Therefore A and C exceed the evidence.

Research boundary

Public structure, synthetic rehearsal.

Inside the draft

  • Publicly available network records
  • Synthetic examples using reserved identifiers
  • Declared source, time, and interpretation limits
  • Aggregate descriptions only if a later study is approved

Outside the draft

  • Private, restricted, or credentialed sources
  • Person-level or organization-contact records
  • Visitor measurement, forms, or account features
  • Raw records or operational network access

Interpretation rule

Observation is not explanation.

The proposed study is observational. A measured association cannot establish cause, intent, ownership, or responsibility.

Any future conclusion would need to identify the clock supporting each observation and state uncertainty, missingness, source coverage, time bounds, and plausible alternative explanations beside every claim.
